# ТЕХНИЧЕСКОЕ ЗАДАНИЕ (ТЗ)
## Модуль Аномалий, Механики Рейдов «Нулевого Слоя» и Демона Максвелла для Android Native Приложения

---

## 1. ВВЕДЕНИЕ И АРХИТЕКТУРНЫЕ ТРЕБОВАНИЯ

Данный документ определяет архитектуру, логику и интерфейсы для реализации системы Аномалий, Рейдов в «Нулевом Слое» и специальных интерактивных сущностей (включая Демона Максвелла) в native-приложении Android (**ANTI-TAR: EIDOS** / **Нулевой Слой**), разрабатываемом на стекe **Kotlin + Jetpack Compose + Room SQLite**.

### Архитектурный стек Android Native:
- **UI Framework:** Jetpack Compose с кастомными Canvas/Shader слоями для глитч-эффектов и эстетики Gothic Tech-RPG / Cyberpunk (`#020304` eidos-bg, `#66FCF1` eidos-cyan, CRT scanlines, Zalgo-text).
- **Локальное хранилище:** Room SQLite ORM (`AppDatabase`) с кешированием состояний.
- **Асинхронность и реактивность:** Kotlin Coroutines (`Dispatchers.IO`) + `StateFlow` / `SharedFlow`.
- **Воспроизведение аудио/видео:** ExoPlayer (для фоновых зацикленных видео DOLL.mp4) + AudioTrack / Web Audio API oscillators для акустической тактильной отдачи.

## 2. КЛАССИФИКАЦИЯ И МЕХАНИКА АНОМАЛИЙ

Аномалии — это динамические нестабильности цифрового пространства EIDOS, влияющие на игровой процесс, интерфейс и характеристики игрока.

### 2.1. Микро-глитчи (Micro-Glitches)

Микро-глитчи возникают спонтанно при совершении бытовых действий игрока в системе (сбор ресурсов, крафт, быстрые клики по UI, разбор инвентаря, совершение шага в рейде).

#### Типы баффов и дебаффов микро-глитчей:
1. `overload` (**Перегрузка**):
   - **Механика:** Увеличивает количество получаемых биокоинов (BC) в рейде на **+50%**.
   - **Длительность:** 3600 секунд (1 час) по умолчанию.
2. `stealth_night` (**Ночная скрытность**):
   - **Механика:** Дает **30% шанс** автоматически проскользнуть мимо патруля или опасной комнаты в рейде без боя и без потери Сигнала.
3. `glitch_berserk` (**Глитч-Берсерк**):
   - **Механика:** Увеличивает критический урон и силу атаки в бою на **+25%**, но накладывает визуальные искажения на UI.
4. `visual_distortion` (**Искажение Реальности / Zalgo**):
   - **Механика:** Переводит текстовые надписи в интерфейсе в формат Zalgo (символы с диакритическими знаками хаоса). Не влияет на боевые статы, но усложняет чтение диалогов и загадок.

#### Логика хранения и обработки в Android Native:
```kotlin
@Entity(tableName = "player_state")
data class PlayerStateEntity(
    @PrimaryKey val uid: Long,
    val isGlitched: Boolean = false,
    val anomalyBuffType: String? = null,
    val anomalyBuffExpiry: Long = 0L // Unix timestamp в секундах
)

// Проверка активности баффа
fun isBuffActive(state: PlayerStateEntity, type: String): Boolean {
    val currentTime = System.currentTimeMillis() / 1000
    return state.isGlitched && state.anomalyBuffType == type && state.anomalyBuffExpiry > currentTime
}
```

### 2.2. Хард-глитчи (Hard Glitches / Критические сбои)

Хард-глитч — это масштабный сбой матрицы, блокирующий доступ к игровым функциям до тех пор, пока пользователь не решит контрольный вопрос терминала (проверка стабильности разума).

#### Логика срабатывания:
1. **Условие возникновения:** Низкий показатель стабильности игрока (`glitches_encountered_count` > 3) либо совершение подозрительно частых кликов без паузы.
2. **Кулдаун:** Мимум 24 часа (`last_hard_glitch_time`) между хард-глитчами.
3. **Блокировка экрана (Screen Lock):** Игрок теряет возможность переходить по вкладкам Хаба. На весь экран выводится прерывание: Zalgo-текст, искаженное изображение и вопросно-ответный блок.
4. **Исход:**
   - **Правильный ответ:** Сбой ликвидируется, игрок получает редкий предмет или восстанавливает биокоины. Кулдаун обновляется на 24 часа.
   - **Неправильный ответ:** Игрок теряет 15% Сигнала (HP) или теряет активные положительные баффы.

### 2.3. Влияние Снаряжения и Аур на Аномалии

В игре присутствуют предметы экипировки, модифицирующие шанс возникновения и поведение аномалий:

| Предмет | Слот | Механика и Логика в Android Native |
| :--- | :--- | :--- |
| `reality_silencer` (Подавитель) | Head (Шлем) | **Полный иммунитет:** Шанс возникновения микро- и хард-глитчей = 0%. Аномалии в рейде блокируются. |
| `death_mask` (Маска Смерти) | Head (Шлем) | **Поиск останков:** Шанс встретить могилы/останки погибших игроков в рейде увеличивается с 30% до **80%**. |
| `scavenger_mask` (Маска Мародера)| Head (Шлем) | **Защита от ловушек:** Снижает базовый урон от ловушек на 5 ед. |
| `nomad_goggles` (Окуляры Номада)| Head (Шлем) | **Детектор тайников:** 5% шанс превратить событие «Пустота» в спавн скрытого тайника с лутом. |
| `karma_inversion` (Инверсия Кармы)| Chip (Чип) | **Инверсия эффектов:** Ловушки восстанавливают **+20% Сигнала**, а Аптечки наносят **-25% урона**. |
| `holo_poverty` (Голограмма Нищеты)| Armor (Броня) | **Ограничение накоплений:** Ограничивает максимальный буфер монет в заезде до 500 BC (всё, что свыше — сгорает). |
| `aegis` (Эгида) | Consumable | **Одноразовый щит:** Автоматически расходуется из инвентаря при получении смертельного урона, предотвращая гибель. |

## 3. МЕХАНИКА И СОБЫТИЯ В «НУЛЕВОМ СЛОЕ» (РЕЙДЫ / СПУСКИ)

«Нулевой Слой» — это пошаговый режим исследования (рейд). Каждый шаг увеличивает показатель «Глубина» (`depth += 1`) и генерирует одно случайное событие.

### 3.1. Генератор событий рейда

На каждом шаге рейда движок Android вычисляет тип события по следующей иерархии:

```
[Шаг в Рейде]
   │
   ├── Есть ли Подавитель Реальности (`reality_silencer`)? ──> ДА ──> Запрет Аномалий
   │
   ├── Проверка на Демона Максвелла (depth > 50 AND random < 0.05 AND !reality_silencer)
   │     └──> [СОБЫТИЕ: Демон Максвелла]
   │
   ├── Проверка на Ночную Скрытность (is_stealth AND random < 0.30)
   │     └──> [СОБЫТИЕ: Безопасный проход в тенях]
   │
   ├── Проверка на Останки Игроков (grave_exists AND random < grave_chance)
   │     └──> [СОБЫТИЕ: Останки Игрока (Found Body)]
   │
   └── Генерация из Базы Данных (Случайный выбор):
         ├── [Trap] Ловушка
         ├── [Loot] Лут / Тайник
         ├── [Heal] Аптечка
         ├── [Riddle] Загадка Терминала
         └── [Combat] Патруль / Босс
```

---

### 3.2. Детальная логика событий Рейда

#### 1. Безопасная зона (Safe Zone):
- Выводится случайная запись из архива лоров (`extra_lore`).
- Сигнал не теряется, игрок может перевести дух.

#### 2. Ловушка (Trap Event):
- **Расчет урона:**
  `base_damage = event_value * difficulty_modifier`
  `damage = max(5, base_damage - player_def)`
- **Взаимодействие с экипировкой:**
  - Если экипирован чип `karma_inversion`: Ловушка лечит player (+20% Signal).
  - Если экипирована `scavenger_mask`: `base_damage` снижается на 5.
  - **Защита от ваншота (One-Shot Protection):** Если у игрока Сигнал > 90%, а полученный урон смертелен, урон снижается так, чтобы оставить **5% Сигнала**.
  - **Предмет `aegis` (Эгида):** При смертельном уроне списывается 1 ед. `aegis`, урон обнуляется.

#### 3. Находка / Лут (Loot Event):
- Формируется награда по формуле с учетом глубин и удачи (`luck`):
  `bonus_xp = event_value * diff * loot_multiplier`
  `coins = random(5, 20) * loot_multiplier`
- Если активен бафф `overload`: `coins = coins * 1.5`.
- **Зашифрованный Кэш (`encrypted_cache`):** C вероятностью **5%** игрок получает ценный кэш в буфер инвентаря, который можно расшифровать в Главном меню после эвакуации.
- Если одета `holo_poverty`: Буфер монет не может превышать 500 BC.

#### 4. Останки Игрока (Found Body / Scavenging):
- Выполняется запрос к БД `get_random_grave(depth)` для поиска реального игрока, погибшего на этой глубине.
- Парсится JSON-структура добычи (`loot_json`).
- Игрок забирает часть биокоинов и предметов из "могилы".

#### 5. Загадки Терминала (Riddles):
- Экран блокируется интерфейсом терминала с текстовым вопросом и 3 вариантами ответов (1 правильный + 2 дистрактора).
- Ограничение по времени на шаг. При правильном ответе дается буст опыта и ресурсов.

## 4. ДЕМОН МАКСВЕЛЛА: ПОЛНАЯ СПЕЦИФИКАЦИЯ И ИСПРАВЛЕНИЕ

> ⚠️ **КРИТИЧЕСКОЕ ИСПРАВЛЕНИЕ И ПРАВИЛО ЛОКАЛИЗАЦИИ:**
> **Демон Максвелла НИ В КОЕМ СЛУЧАЕ НЕ ДОЛЖЕН НАХОДИТЬСЯ В ГЛАВНОМ МЕНЮ ИЛИ ХАБЕ!**
> Размещение его в Главном меню агентским кодом является **грубой ошибкой архитектуры**. Демон Максвелла — это энтропийная аномалия глубокого погружения в «Нулевой Слой».

### 4.1. Условия и место появления

1. **Только внутри рейда «Нулевой Слой»** (Raid Session View).
2. **Минимальная глубина:** `depth > 50`.
3. **Шанс появления:** **5%** за каждый шаг на глубине более 50 (при отсутствии у игрока шлема `reality_silencer`).
4. **Визуальный стиль появления:** Оверлей экранa окрашивается в тёмно-красный цвет с энтропийным шумом. Воспроизводится низкочастотный гул (Audio Sub-bass Synth).

---

### 4.2. Игровая механика сделки Демона Максвелла

Демон Максвелла предлагает игроку сыграть в энтропийную игру — поставить на кон свой жизненный Сигнал (HP) ради редких ресурсов, либо часть накопленного в рейде лута ради спасения жизни.

```
                   [ВСТРЕЧА С ДЕМОНОМ МАКСВЕЛЛА]
                                 │
         ┌───────────────────────┴───────────────────────┐
         ▼                                               ▼
[СТАВКА 1: 30% СИГНАЛА (HP)]                 [СТАВКА 2: 50% НАКОПЛЕННОГО ЛУТА]
         │                                               │
 ┌───────┴───────┐                                ┌───────┴───────┐
 ▼               ▼                                ▼               ▼
[УСПЕХ 50%]    [ПРОВАЛ 50%]                      [УСПЕХ 50%]    [ПРОВАЛ 50%]
Получение       Потеря 30%                       Восстановление Сгорает 50%
редкого лута    Сигнала                          50% Сигнала    накопленного
и 500 BC        (Возможна смерть!)               (HP)           буферного лута
```

---

### 4.3. Подробная логика обработки ставок

#### Вариант А: «Ставка: 30% Сигнала» (`anomaly_bet_hp`)
1. **Предварительная проверка:**
   - Если текущий Сигнал игрока <= 30%, приложение выводит предупреждение о фатальном риске: *«Твой сигнал слишком слаб. Демон поглотит твой разум полностью!»*
2. **Расчет исхода (50 / 50):**
   - **УСПЕХ (50%):**
     - Начисляется +500 BC в буфер рейда.
     - Добавляется редкий предмет или `encrypted_cache`.
     - Выводится сообщение: `«Демон удовлетворен энтропией. Ты получил древние данные.»`
   - **ПРОВАЛ (50%):**
     - Сигнал снижается на **30%**: `new_signal = max(0, current_signal - 30)`.
     - **Смерть игрока:** Если `new_signal <= 0`, рейд незамедлительно завершается. Статус рейда меняется на `SIGNAL LOST`. Накопленный лут сгорает, а останки игрока сохраняются в таблицу `graves` для других участников.

#### Вариант Б: «Ставка: 50% Накопленного Лута» (`anomaly_bet_buffer`)
1. **Предварительная проверка:**
   - Если буфер лута пуст (`buffer_coins == 0` и нет найденных предметов в рейде), кнопка заблокирована с плашкой: *«Тебе нечего предложить Демону.»*
2. **Расчет исхода (50 / 50):**
   - **УСПЕХ (50%):**
     - Восстанавливается **+50% Сигнала**: `new_signal = min(100, current_signal + 50)`.
     - Буфер лута сохраняется.
     - Выводится сообщение: `«Демон принял виртуальную жертву и восстановил твою матрицу!»`
   - **ПРОВАЛ (50%):**
     - Накопленный в текущем рейде буфер монет и предметов уменьшается на **50%**: `buffer_coins = buffer_coins / 2`.
     - Выводится сообщение: `«Демон забрал твой лут и исчез во тьме...»`

## 5. РЕЗЮМЕ ТЕСТИРОВАНИЯ И ВЕРИФИКАЦИИ

1. **Изоляция Демона Максвелла:** Проверить, что в `Hub.jsx` и `menu.py` отсутствуют ссылки или кнопки вызова Демона Максвелла. Он должен вызываться исключительно из `modules/services/raid.py` и экрана рейда Android.
2. **Валидация БД:** Поля `anomaly_buff_type` и `anomaly_buff_expiry` должны корректно сбрасываться при истечении времени таймера.
3. **Обработка смертельных исходов:** Проверить, что ставка 30% Сигнала при Сигнале <= 30% при провале приводит к мгновенной и корректной генерации экрана `SIGNAL LOST` и созданию могилы (`grave`).
