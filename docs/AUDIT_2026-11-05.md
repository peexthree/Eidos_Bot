# Аудит репозитория Eidos RPG - 2026-11-05

Полный аудит: безопасность, архитектура, данные и сборка. Игра в разработке, в
продакшене не была. Статус исправлений обновляется по мере внедрения.

## Исправлено

### Безопасность Supabase (критично)
- **RLS app_players**: убраны обходы `auth.role() = 'anon'/'authenticated'`;
  только строгая сверка с `auth.uid()` по device_id/id.
- **Защита экономики**: триггер `enforce_economy_limits` - клиентские PATCH
  не могут поднять biocoins > +25k за раз (бюджет 60k/мин), level > +5,
  max_depth > +50, kills > +500. RPC помечают записи через
  `SET LOCAL eidos.server_ctx = 'trusted'`.
- **sync_player_inventory**: `auth.uid() IS NULL` теперь RAISE EXCEPTION
  (раньше anon-запрос полностью пропускал проверку владельца).
- **process_raid_reward**: depth клампится к серверному max_depth + 25
  (абсолютный кап 10000), кулдаун 10с. Схема `depth=10^6 -> 5*10^7 монет` закрыта.
- **resolve_pvp_match**: кулдаун 30с, запрет само-матча (была XP-петля),
  защита программ рандомизирована (была предсказуемая секунда NOW()).
- **verify_and_record_purchase**: только service_role (5-аргументная
  сигнатура с p_player_id), потолок начисления, защита от replay по token_hash.
- **Гостевые пароли**: SecureRandom 32 симв. в EncryptedSharedPreferences
  вместо `EidosAnonPassword_ + hashCode()`; legacy-fallback сохраняет доступ
  старых гостей. При недоступном шифрования пароль не пишется на диск.
- **Токены сессии**: при fallback на незашифрованные prefs токены держатся
  только в памяти (перезапуск = повторный вход), legacy plaintext затирается.

### Сборка и инфраструктура
- **GEMINI_API_KEY** - только в debug-сборках; release использует локальную
  симуляцию (ключ больше не в APK).
- **Release-подпись** - из keystore.properties (в .gitignore), fallback на
  debug-ключ с предупреждением. Пример: keystore.properties.example.
- **CI** - .github/workflows/android-ci.yml: compileDebugKotlin +
  testDebugUnitTest на push/PR, отчёты тестов при падении.
- **rootProject.name** - ASCII (EidosZeroLayer вместо кириллицы).

### Серверная верификация покупок
- supabase/functions/verify-purchase (Deno): JWT -> RS256 service account ->
  Google Play API -> RPC ledger. Сумма берётся только из серверного каталога
  PRODUCT_CATALOG. Инструкция: supabase/functions/README.md.
- Клиент репортит покупку fire-and-forget (мок-токены не отправляет);
  локальное начисление сохранено до включения Play-биллинга.

### Данные
- **data/supabase_hardening_v2.sql** - единственный актуальный SQL
  (самодостаточный, идемпотентный): таблицы, сид каталога цен, индексы, RLS,
  триггер, rate-limiter, все RPC. Старые файлы помечены DEPRECATED.
- Спасательный бэкап БД перед разрушительной миграцией Room
  (eidos_database_rescue_backup) - данные версий < 10 восстановимы.
- Миграция Room 12->13: композитный индекс game_logs(uid, timestamp) для
  trimOldLogs под dbMutex.
- Устаревший Telegram-контент перенесён в data/legacy/, добавлен data/README.md.

### Concurrency и качество кода
- OkHttp таймауты 10/10/10/15с (были дефолтные).
- Сеть вынесена из-под dbMutex: лог в Supabase через backgroundScope.
- 11 публичных мутаторов приведены к паттерну `dbMutex.withLock { internalUnsafe* }`
  (scanSector, buyMetaUpgrade, крафтовые функции, ensureDevicePlayerExists...).
- Атомарная repository.regenerateEnergy() вместо двух дублированных блоков
  в MainViewModel (устранена гонка read-modify-write из параллельных корутин).
- Единый launchRaidAction в MainViewModel: боевые/рейдовые точки входа
  логируют исключения вместо падения приложения (8 обёрток).
- Стабильные key= в Lazy-списках (RaidScreen, PvpScreen x3, TerminalLog,
  RelicShowcase); JuiceUIComponents/EidosTerminalDialog осознанно без ключей
  (нет стабильного уникального идентификатора - дубликаты ключей крэшат).
- printStackTrace -> Log по проекту; диагностика в catch EidosImage.
- Проекция колонок вместо select=* в лидерборд-запросах.
