## 1. ЦЕЛЬ

Поднять продакшн-качество игры по трём направлениям - картинка, звук, процессы разработки - без смены стека и без выхода в онлайн. Весь новый контент и проверки производятся через подключённые AI-утилиты (плагины ZCode), ручной труд сводится к согласованию результатов.

**Измеримый результат:**
- CI-пайплайн с Compose UI-тестами зелёный, бейдж в README
- Весь UI-арт приведён к единому стилю, иконки в векторе, вес графики в APK снижен минимум на 20%
- Все озвучки и SFX выровнены по громкости, разброс не превышает целевой LUFS-коридор
- Баланс-модель экономики подтверждена симуляцией, правки внесены через content.json
- Полный скриншот-прогон всех экранов запускается одной командой

## 2. РАМКИ, ЗАПРЕТЫ, ОГРАНИЧЕНИЯ

- Стек не меняем: Kotlin, Jetpack Compose, Room, Media3 ExoPlayer, offline-first
- 3D-направление закрыто решением владельца проекта - генерация 3D-ассетов (Tripo, Rodin, Blender) в рамки не входит и не предлагается
- Движковые MCP (Unity, Unreal) не применимы - не используем
- Онлайн-бэкенд не подключаем (Supabase остаётся в текущем состоянии)
- Механики не трогаем без обоснования через баланс-модель: лимиты сокетов 4/3/2/1, тип-сохраняющий синтез, идемпотентные клеймы наград, смерть/сброс
- Учитывать Mimosa-гейт: не использовать имена присвоений с token, аккуратно с JSON-литералами и SSRF-паттернами; deny-Edit может не примениться - проверять результат правки
- Соблюдать жёсткие уроки разработки (LEARNINGS.md): init-порядок MainViewModel, adb-диагностика через эмулятор-плагин

## 4. ПАКЕТЫ РАБОТ

### П0. CI-фундамент (github) - ПРИОРИТЕТ 1

Последний открытый пункт аудита. Делается первым, остальные пакеты опираются на зелёную базу.

Задачи:
- GitHub Actions workflow: assembleDebug + unit-тесты + connectedAndroidTest (Compose UI-тесты) на каждый PR в main
- Кэш Gradle, лимит времени пайплайна - 15 минут
- Публикация артефактов: отчёты тестов, скриншоты упавших UI-тестов
- Статус-бейдж в README
- Первая партия UI-тестов: вход в хаб, переход в кузню, клейм награды (идемпотентность), экран инвентаря

Приёмка:

Артефакты: .github/workflows/ci.yml, тесты в app/src/androidTest/

### П1. Арт-ревизия (photocraft + vectorcraft) - ПРИОРИТЕТ 2

Текущее состояние: 185 jpg + 63 png + 6 webp в drawable, векторных иконок нет, папка assets/icons/ требует ревизии.

Задачи:
- Инвентаризация: сопоставить каждый drawable с местом использования в коде; список мёртвых ассетов на удаление (git откат возможен)
- Единый стиль фонов: один пресет цветокоррекции/тонировки для всех bg_* через photocraft, до-апскейл под 1080p+, конверсия jpg -> webp (контроль артефактов)
- Векторизация UI-иконок: иконки предметов и UI-глифы перерисовать в vectorcraft как SVG, импорт в VectorDrawable; приоритет - то, что мелкое и частое (иконки инвентаря, бейджи, кнопки)
- Баннеры и рамки (banner_hazard_stripes и подобные) - в вектор
- Контроль веса: цель -20% суммарного веса графики

Приёмка:
- A/B-сравнение до/после на скриншотах эмулятора, владелец утверждает
- Список удалённых мёртвых ассетов приложен к PR
- APK вес не вырос ни в одном density-бакете

Артефакты: asset_inventory.csv (обновлённый), PR с графикой, отчёт по весу

### П2. UI-прототипы экранов (designcraft + design skill) - ПРИОРИТЕТ 2, параллельно с П1

Задачи:
- Макеты пяти ключевых экранов: хаб, кузня (реестр ковки), инвентарь, спуск QTE, Терминал

Приёмка:

Артефакты: docs/mockups/ - 5 макетов + diff-листы

### П3. Звук (soundcraft) - ПРИОРИТЕТ 3

Текущее состояние: 3 BGM (mp3), ~25 EVA-озвучек (wav), SFX, шаги step1-5, 4 видео-фона (mp4).

Задачи:
- Нормализация громкости всех raw/*.wav и SFX к целевому коридору (EVA-озвучки и SFX - свои референсные уровни; финальные значения зафиксировать в таблице)
- Чистка шумов: шаги, sfx_drone_radio, sfx_tape_rewind
- Проверка стыков BGM: нет ли щелчков/обрывов на переходах, при необходимости подровнять fade в soundcraft
- 2-3 новых SFX под актуальные механики (QTE-успех/провал, активация шлема Скорости) - по согласованию
- Видео-фоны: контроль веса, при необходимости перекодирование с сохранением качества

Приёмка:
- Таблица "файл - исходный LUFS - целевой LUFS - готово" приложена
- Прогон в игре на эмуляторе: владелец проходит день игры и подтверждает комфорт громкости

Артефакты: обновлённые файлы в res/raw/, таблица нормализации в docs/

### П4. Баланс-модель экономики (spreadsheets) - ПРИОРИТЕТ 3

Приёмка:

## 5. ПОРЯДОК И ЗАВИСИМОСТИ

```
П0 (CI)
 |
 +-- П6 (автопрогон, опирается на CI-сборку)
 +-- П1 (арт) --> П2 (макеты) --> вёрстка PR-ами
 +-- П3 (звук)
 +-- П4 (баланс) --> правки content.json
 +-- П5 (диаграммы)
 П7 - постоянно, П8 - по готовности ядра
```

П1 и П2 идут параллельно, но вёрстка экрана начинается только после утверждения его макета. П4 опережает любые ручные правки экономики в контенте.

## 6. МЕТРИКИ УСПЕХА

| Метрика | Было | Цель |
|---|---|---|
| UI-тесты в CI | нет | да, зелёный пайплайн |
| Вес графики в APK | база (замерить в П1) | -20% |
| Векторные иконки | 3 xml | все UI-иконки |
| Разброс громкости озвучек | не измерен | в целевом LUFS-коридоре |
| Скриншот-прогон | вручную | 1 команда, до 5 минут |
| Баланс-правки | без модели | каждая через симуляцию |

## 7. РИСКИ И ОТКАТЫ

- Векторизация меняет вид иконок - решает владелец по A/B, откат через git
- Конверсия jpg -> webp может дать артефакты на градиентах - контролировать по скриншотам, проблемные файлы остаются в jpg
- Нормализация может задеть тихие EVA-файлы с эффектами - слушать выборочно, не только по метрикам
- Правки баланса меняют опыт игроков - вносить малыми порциями, каждая с симуляцией и тестами
- Mimosa deny-Edit не гарантирует применение правки - после каждого Edit проверять фактическое содержимое файла
